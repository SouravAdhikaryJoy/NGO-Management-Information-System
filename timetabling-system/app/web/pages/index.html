How it works

  1. 01

    Fill the workbook

    Download the blank Excel template — one sheet per thing your university has: Rooms, TimeSlots, Teachers, Courses, ClassGroups… Or press Load demo data to explore with a ready-made sample.

  2. 02

    Import & check

    Upload the workbook. Every row is validated first — if something is wrong you get the exact sheet, row and field, and nothing is half-saved. Re-uploading an updated file simply updates the records.

  3. 03

    Run the solver

    Phase 1 places every class with no clashes at all. Phase 2 then improves quality: fewer idle gaps, sensible lunch breaks, preferred slots honoured. Progress is shown live.

  4. 04

    Review, export, adjust

    Browse the routine on the timetable page, download it as Excel, CSV, calendar (.ics) or PDF — or edit the Excel master sheet by hand and re-upload it; edits are checked against every rule.

Good to know

What is a “hard constraint”?
A rule that must never break: a room, teacher or class group can’t be in two places at once, rooms must be big enough and of the right type, teachers must be available and qualified. The solver guarantees all 14 of them — the feasibility report in every export shows zero violations.
What is a “soft constraint”?
A quality wish with a weight: compact days, no long teaching runs, lunch kept free, difficult courses in the morning. The solver minimises the total weighted penalty, and you can tune every weight under Config → weights.
Can I adjust the result by hand?
Yes. Export the Excel routine, move any class to another cell of the MasterTimetable sheet (or change the teacher code in the cell), and upload it at POST /api/v1/import/edits. Each edit is re-checked against every hard rule; invalid edits are rejected individually with the reason.
Is a run reproducible?
Every run records its random seed, iteration counts, runtime and a snapshot of all weights and settings — so the same input and seed give the same routine.
